# Локальные логи

Начиная с 1.9.1 приложение создаёт папку логов на каждом устройстве при запуске.
Открыть её можно через **Помощь → Открыть папку логов**, в том числе без открытого PDF.

В sandbox-сборке папка обычно находится здесь:

```text
~/Library/Containers/com.botplus.pdfeditor/Data/Library/Logs/BotPlus PDF Editor/
```

Без sandbox используется `~/Library/Logs/BotPlus PDF Editor/`.
Приложение получает фактический путь через системный API Library; пункт меню
открывает именно его.

Сохраняются версия/номер сборки, версия macOS и архитектура, запуск/завершение,
открытие и замена PDF (число страниц), команды функций, коды ошибок открытия,
сохранения и редактирования, а также сообщения стандартного потока ошибок stderr.
Служебные записи приложения не содержат текста PDF, паролей или полных путей
документов. Вывод системных библиотек сохраняется как есть и может содержать пути.

Каждый файл `session-*.log` ограничен 2 МБ, сохраняются до восьми последних файлов
(до 16 МБ). Записи датируются в UTC. Папка и файлы доступны владельцу пользователя.
Ротация и запись синхронизированы, обработчик stderr работает независимо от UI.
Ошибка записи лога не останавливает приложение. Логи автоматически никуда
не отправляются; при обращении за поддержкой можно приложить нужные `.log`.

При обычном выходе записывается `session_end clean=true`. Если предыдущий процесс
завершился без этой записи и его уже нет, следующий запуск отмечает
`previous_session_ended_without_clean_shutdown`: это может быть сбой, принудительное
завершение или выключение питания. Этот маркер не является диагнозом причины.

Полные отчёты macOS `.ips` остаются в системной диагностике. Приложение не ставит
обработчики SIGTRAP/SIGABRT и не пытается продолжать работу после аварии. Последние
байты stderr при мгновенном завершении процесса могут не успеть попасть в файл.

# Исправление сбоя 1.9

Оба присланных отчёта от 3–4 ноября 2026 показывают один стек:

```text
PDFKit.PDFDocument.formFillingQueue
PDFPageAnalyzerV2 → PDFAnnotation.updateAnnotationEffect
@objc PDFViewerView.document.getter
swift_task_checkIsolatedSwift → _dispatch_assert_queue_fail → SIGTRAP
```

В 1.9 наблюдатель `didSet` переопределённого `document` создавал Swift getter
с проверкой MainActor, хотя PDFKit вызывал его из фоновой очереди распознавания форм.
В 1.9.1 переопределение удалено: getter наследуется непосредственно от PDFView.
Замена документа и сброс выделения выполняются методом `installDocument` на UI-потоке.
Проверки покрывают фоновое чтение через Objective-C, наследование реализации getter,
сброс выделения при замене PDF, перехват stderr, параллельную запись и ротацию логов.
Исходный PDF, на котором произошёл сбой, не приложен; точный сценарий открытия
этого документа и полная приёмка на пользовательском устройстве остаются для проверки.
